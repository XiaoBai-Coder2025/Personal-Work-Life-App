# 个人工作生活 App —— 第一版设计

日期：2026-09-21
状态：待确认

## 1. 目标

一个只在本机浏览器里打开的个人工作生活工具。数据存在这台电脑的文件里，刷新、关闭、重启都不丢。单人使用，不登录，不部署。

第一版要做：

- 七个模块：首页总览、今日计划、日历日程、任务追踪、地图工具、AI 助手、数据与设置（编号沿用原始编号 10）
- 一套共用的"智能排布"能力，同时服务今日计划、日历日程、任务追踪、首页和地图，不各排一套
- 只有 AI 助手和地图需要联网，其余功能断网可用

第一版不做：

- 账号、登录、云同步、多设备、手机端、部署上线
- 多人协作、分享、评论
- 已删除的 7、8、9 类模块（记账、健康、读书等）
- 自动爬取网站报名信息；短信、邮件、微信推送
- 离线地图瓦片下载；复杂统计报表和大屏图表

## 2. 运行形态

本地 Node 服务 + 浏览器页面。Node 24 已在本机，无需安装其他工具。

- 启动方式：双击项目根目录的 `启动.bat`，或执行 `npm start`，浏览器打开 `http://localhost:4317`
- 服务只做五件事：提供页面、读写本机数据文件、提取上传文件的正文、代理高德 Web 服务请求、代理 AI 请求
- 页面用原生 HTML/CSS/JS，没有构建步骤，改完刷新即生效
- 关掉服务再启动，数据照旧

为什么不是"双击 HTML 文件"：`file://` 协议下浏览器不允许调用高德和 AI 接口，数据也只能放在浏览器缓存里，清理缓存或换浏览器就丢失，不满足"不能丢"。

## 3. 目录结构

```
Application_Off_Line_Version/
├─ server.js              本地服务入口（路由、静态文件、转发高德与 AI）
├─ package.json           只有启动和测试脚本
├─ 启动.bat               双击即启动并打开浏览器
├─ src/
│  ├─ paths.js            路径与端口等常量
│  ├─ store.js            数据文件的原子读写与校验
│  ├─ backup.js           全部数据的导出与导入
│  ├─ amap.js             高德 Web 服务代理 + 结果缓存
│  ├─ ai.js               AI 转发（支持流式）
│  └─ extract.js          文件正文提取（PDF / Word / 文本）
├─ web/
│  ├─ index.html
│  ├─ app.js              路由与整体布局
│  ├─ styles.css
│  ├─ core/               数据客户端、日期工具、通用组件、排布引擎
│  └─ modules/            七个模块各一个文件
├─ test/                  自动化测试

├─ backups/               自动备份（不进版本库）
└─ docs/                  设计与计划文档
```

每个文件只干一件事，删掉某个模块不影响其他模块。

## 4. 数据怎么存

`data/` 下按主题分成几个 JSON 文件，每个文件形如 `{ "version": 1, "items": [...] }`：

| 文件 | 内容 |
| --- | --- |
| `profile.json` | 身份模板、作息偏好、默认通勤方式 |
| `places.json` | 常用地址（家、学校、公司等，含坐标与常用交通方式） |
| `routine.json` | 固定课表 / 工作表（星期、时段、地点、生效区间） |
| `events.json` | 日程事件，含比赛、申请等临时日程；标记来源（手动 / 文件导入 / AI） |
| `plans.json` | 每天的时间块安排（排布草稿经确认后写入这里） |
| `tasks.json` | 长周期任务（阶段、每段时段、每天投入上限、交付日、风险与依赖） |
| `notes.json` | 快速备忘 |
| `pending.json` | 等确认的草稿（AI 或文件导入产出，未确认前不进正式数据） |
| `settings.json` | 高德 JS Key 与安全密钥、AI 服务商与 Key、界面偏好 |

写入安全：

- 先写临时文件，再原子替换，避免写一半断电留下半个文件
- 替换前把上一版保留为 `.bak`
- 启动时校验 JSON，损坏则回退备份并在界面上提示

备份：设置页提供"导出备份"，生成一个带日期的 JSON 文件；"导入备份"整体覆盖现有数据，覆盖前自动把当前数据另存一份。

密钥：高德 JS Key、高德安全密钥、AI Key 都存在 `data/settings.json`，不进代码、不提交版本库，界面上默认打码显示。

## 5. 七个模块各自做什么

**首页总览**：只负责"一眼看完"和"随手记一句"。以抽屉呈现即将截止、今天的计划、长周期任务、给你的建议、快速备忘和今天要去的地方；其中"给你的建议"结合身份、地点、天气与突发情况给出提示，并标注依据。不做深度编辑，点击跳到对应模块。

**今日计划**：按时间顺序排出来的一天。来自智能排布的草稿放在最上方，可整块采纳、逐条调整、勾选完成、顺延到明天，也可以手动插一条。

**日历日程**：看长期节奏。月视图里固定课表/工作表作为底色，临时日程与截止日期单独高亮并标出来源；同一天时间冲突直接标红。不做周视图以外的复杂视图。

**任务追踪**：以长周期任务为单位。每条任务有阶段（可增删、可切换）、进程条、各阶段占用的具体时段、每天投入上限与交付日；同一天分配给多个阶段时，各段时间之和不得超过当天上限。它不是每日任务列表，而是长期推进的台账，并支持把"今天该做的那一段"排进今日计划。

**地图工具**：空间视角。地图铺满模块，左侧为地点与周边，右侧为路线；支持搜索并标记多个地点、逐段选择交通方式、调整经过顺序并做顺序优化、按平日或节假日估算耗时；常用地址一键设为起终点。路径耗时会被智能排布用于计算出发时间。

**AI 助手**：配好 Key 后可用。能读取本地数据回答"今天还有什么没做""这条任务卡在哪"，能写总结、能把一段文件内容变成待确认的日程草稿，也能按任务的交付日重新安排每天的时段。所有产出先进 `pending.json`，你在界面上确认后才写入正式数据。

**数据与设置**：身份模板、常用地址、课表/工作表、两把 Key（高德 JS、AI）、导出与导入备份、清空数据。编号沿用 10，界面上不显示序号。

## 6. 智能排布（共用核心）

输入：身份与作息偏好、常用地址、固定课表/工作表、已有日程与截止日期、长周期任务的阶段与时段、每天投入上限。

当天怎么排：

1. 把当天的固定课表/工作表当锚点，视为不可移动
2. 收集当天到期和临近的任务时段、截止事项，按紧迫度与重要度排序
3. 在锚点之间算出可用空档，扣除用餐与休息的默认缓冲
4. 把任务时段按顺序填进空档（每段可填预计时长，不填按 30 分钟算）
5. 涉及地点切换时，用高德路径规划补上路上耗时，给出"几点该出门"（结果缓存，避免重复请求）
6. 输出草稿，等你确认后才写进 `plans.json`

长期怎么排：把未来一段时间的截止日期和临时日程摊到日历上，做标注、提醒和冲突检测，并给出提前量建议。第一版不自动把每天塞满。

排布结果永远是草稿，不会自己变成你的计划。

## 7. 外部接口与 Key

- 高德 JS Key：浏览器内渲染可拖拽缩放的地图，路径规划、地理编码、周边搜索都由它承担，不再需要 Web 服务 Key
- 高德安全密钥：不放进页面，由本机服务按高德支持的代理方式代转，页面里只有 JS Key
- AI：按 OpenAI 兼容接口填写（服务地址 + 模型名 + Key），由本地服务转发，浏览器拿不到 Key，支持流式输出

## 8. 出错怎么办

- 没配 Key：地图模块和 AI 助手显示"去设置里填 Key"，其他功能照常
- 接口调用失败：界面明确报错并可重试，不静默失败，不写入半成品数据
- 断网：除地图、AI 和文件导入外，其余功能正常
- 数据文件损坏：启动时用备份恢复并提示
- AI 返回内容无法解析成日程：原样展示返回内容，让你手动处理，不猜、不编造日期

## 9. 文件导入的范围

支持读取 `.txt` `.md` `.csv` `.pdf` `.docx`，提取正文后交给 AI 抽出事项、日期和截止时间，生成待确认草稿。

不支持的：Excel 表格请先另存为 CSV；扫描件等图片型 PDF 无法提取文字时会明确提示失败，不猜内容。这样只为 PDF 和 Word 各引一个成熟的提取库，不引入更多依赖。

## 10. 怎么验证

- 排布引擎是纯函数，用 Node 自带的测试工具写单元测试，覆盖：空档计算、截止日期排序、冲突检测、地点切换时补路上时间
- 存储层测试：原子写入、并发写入、损坏文件回退备份
- 手动验收清单：刷新页面数据仍在；关掉服务再启动数据仍在；断网后除地图与 AI 外都能用；AI Key 与高德安全密钥不出现在页面源码里（高德 JS Key 按设计必须出现）
- 每次改完都跑测试，不通过不继续

## 11. 几个明确的技术取舍

- 单人单机、数据量小，用 JSON 文件足够，不上数据库
- 不引入前端框架和打包工具，避免"要先编译才能用"的复杂度
- 外部依赖只保留必要的文件提取库，其余用 Node 自带能力
- 长期排布只做标注、提醒和冲突提示，不做自动排满
- AI 只产出草稿，写入正式数据必须经你确认
